# UI_GUIDELINES.md

# Tamam Marketplace UI / UX Guidelines

Version: 1.0

---

# Design Philosophy

Tamam is not a traditional classifieds website.

The interface must feel modern, clean, trustworthy, and effortless.

Every screen should help users complete their tasks quickly with minimal distractions.

The design should prioritize usability over decoration.

---

# Design Keywords

- Modern
- Minimal
- Premium
- Clean
- Elegant
- Fast
- Trustworthy
- Mobile First

---

# Design Inspiration

The design language should be inspired by the simplicity and usability of:

- Apple
- Airbnb
- Stripe
- Notion
- Linear

Do not copy these products.

Use them only as inspiration for quality and usability.

---

# User Experience Principles

Every feature should satisfy at least one of the following:

- Save time
- Reduce clicks
- Increase trust
- Improve readability
- Reduce confusion

---

# Navigation

Navigation must always be simple.

Users should never feel lost.

Maximum navigation depth:

3 levels.

Always provide:

- Breadcrumbs
- Clear page titles
- Back navigation where appropriate

---

# Homepage

The homepage must immediately answer three questions:

1. What is Tamam?
2. What can I find here?
3. What should I do next?

Homepage priorities:

- Search Bar
- Categories
- Featured Listings
- Latest Listings
- Popular Categories
- Promotional Banner (optional)

---

# Search

Search is the most important feature.

Requirements:

- Large search bar
- Instant suggestions
- Recent searches
- Popular searches
- Smart filtering
- Sorting options

Search should be available on every page.

---

# Listing Cards

Each listing card should include:

- Main Image
- Title
- Price
- Location
- Time Posted
- Verification Badge
- Favorite Button

Optional:

- Featured Badge
- Premium Badge

Cards must be clean and readable.

---

# Listing Details Page

Order of information:

1. Images
2. Title
3. Price
4. Seller Information
5. Contact Buttons
6. Description
7. Specifications
8. Location
9. Similar Listings

Primary action buttons must always remain visible on mobile.

---

# Forms

Forms should be short.

Break long forms into steps.

Always include:

- Labels
- Validation
- Error Messages
- Success Feedback

Never rely on placeholders as labels.

---

# Typography

Use a modern sans-serif font.

Preferred:

English:

Inter

Arabic:

IBM Plex Sans Arabic

or

Noto Sans Arabic

Use a consistent typography scale.

Avoid more than 6 text sizes.

---

# Color Palette

Primary

Qatar Maroon

Secondary

White

Neutral

Gray Scale

Success

Green

Warning

Orange

Danger

Red

Information

Blue

Do not use excessive colors.

---

# Border Radius

Small

6px

Medium

10px

Large

16px

Extra Large

24px

Use consistent radius across the platform.

---

# Shadows

Soft shadows only.

Avoid heavy shadows.

The interface should feel light and premium.

---

# Buttons

Primary

Filled

Secondary

Outlined

Danger

Red

Text Button

Minimal

Buttons must have:

Hover State

Active State

Loading State

Disabled State

---

# Icons

Use one icon library only.

Recommended:

Lucide Icons

Icons should always accompany important actions.

Never overuse icons.

---

# Spacing

Use an 8-point spacing system.

Examples:

8

16

24

32

40

48

64

Maintain consistent spacing across all screens.

---

# Grid System

Desktop

12 Columns

Tablet

8 Columns

Mobile

4 Columns

---

# Images

High quality only.

Consistent aspect ratio.

Lazy loading.

Support WebP.

Compress automatically.

---

# Animations

Animations should be subtle.

Duration:

150–250ms

Avoid unnecessary motion.

Never delay user interaction.

---

# Responsive Design

Design Mobile First.

Support:

Mobile

Tablet

Laptop

Desktop

Ultra Wide

---

# Accessibility

Support keyboard navigation.

Proper color contrast.

Visible focus states.

Meaningful labels.

ARIA where appropriate.

Readable font sizes.

---

# Loading States

Every async action should have:

Skeleton Loader

or

Loading Spinner

Never leave blank spaces.

---

# Empty States

Every empty page should explain:

Why it is empty.

What the user can do next.

Include a clear Call-To-Action.

---

# Error Pages

Provide custom pages for:

404

403

500

Network Error

Each page should help the user recover.

---

# Notifications

Use toast notifications.

Messages should be:

Short

Clear

Helpful

Avoid technical language.

---

# User Dashboard

Dashboard sections:

Overview

My Listings

Messages

Favorites

Notifications

Subscription

Settings

Verification

---

# Admin Dashboard

Prioritize information.

Show KPIs.

Recent Activity.

Pending Reviews.

Reported Listings.

Revenue.

Users.

Analytics.

---

# Dark Mode

Support Dark Mode from day one.

All colors must have dark equivalents.

Avoid pure black.

---

# Design System

Every reusable UI element should become a component.

Examples:

Button

Card

Input

Modal

Dropdown

Avatar

Badge

Tag

Toast

Dialog

Pagination

Tabs

Accordion

---

# Performance Rules

Avoid heavy graphics.

Minimize animations.

Lazy load images.

Lazy load pages.

Optimize fonts.

Optimize SVG icons.

---

# UX Rules

Never surprise the user.

Never hide important actions.

Never use more than one primary action per screen.

Reduce unnecessary confirmations.

Reduce scrolling where possible.

Keep important actions reachable with the thumb on mobile.

---

# Final Design Principle

Every screen should answer:

What is this page?

What can I do here?

What should I do next?

If these answers are not immediately obvious,

the design must be improved.
